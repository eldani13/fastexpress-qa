# DEF-004: la API responde error 500 con números enormes

| Campo | Detalle |
|---|---|
| Estado | **Nuevo**: registrado como issue; pendiente de asignar |
| Issue | [#1](https://github.com/eldani13/fastexpress-api/issues/1) (repo API) |
| Módulo | Backend (lógica de negocio) |
| Severidad / prioridad propuestas | Alta / Alta |
| Detectado | 2026-10-13, sesión exploratoria 1; reconfirmado 2026-10-24 en Swagger |
| Entorno | macOS, FastAPI + uvicorn en `127.0.0.1:8000` (Swagger `/docs`) |
| Frecuencia | Siempre |
| Prueba de reproducción | `test_DEF004_numeros_enormes_se_rechazan_sin_error_500` (3 casos, `xfail`) |

## Pasos para reproducir

1. Iniciar el servidor.
2. Enviar `POST /api/v1/cotizaciones` con
   `{"peso": "99999999999999999999999999999", "tipo_cliente": "NUEVO", "tipo_envio": "ESTANDAR", "monto_declarado": 50}`
   (29 nueves).

## Resultado esperado

`422` con código `LIMITE_PESO_EXCEDIDO`: según BR-02, todo peso mayor a 20.00 kg se rechaza.
La especificación de la API establece que un 500 nunca es una respuesta válida.

## Resultado obtenido

`500 Internal Server Error`, sin el formato de error de la API.

## Otras entradas que lo producen

| Campo | Valor | Respuesta |
|---|---|---|
| `peso` | `1e1000000` | 500 |
| `peso` | `1e308` (número JSON) | 500 |
| `monto_declarado` | 29 nueves | 500 |
| `peso` | `1E2` | 422 correcto (no reproduce) |

## Notas para el desarrollador

El error aparece con números de más de unos 26 dígitos enteros. Valores grandes pero razonables (`1E2`, `25`) se rechazan bien.
